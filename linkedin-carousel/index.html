01 — The Protocol
What even is MCP?
Model Context Protocol is a standard for connecting AI models to external tools and data — think USB-C for AI agents.
🔧
Tools — Functions the AI can call with strict JSON schemas (query users, search SOPs, etc.)
📄
Resources — Read-only data the AI can pull for context (DB schemas, SOP catalogs, logs)
💬
Prompts — Reusable system prompts that adapt to role and incident severity

03 — Safety
Human-in-the-loop is non-negotiable
AI shouldn't delete users or modify critical data without a human saying "yes."
🛑
Sensitive tools are gated — add_user and deactivate_user require approval before execution
📋
Approval queue — Pending requests show up in the Next.js dashboard for admins to review
📝
Full audit trail — Every tool call is logged with actor, decision, request, and result
✅
Only then it runs — Approved actions are executed and logged again for traceability

One query, three backends

05 — Security
Auth at the protocol layer
Every MCP tool call goes through JWT verification and scope-based authorization.
🔐
OAuth + JWT via JWKS — Clerk handles identity, server verifies tokens against JWKS endpoint
🎯
Scoped permissions — read:users, write:users, read:sops, write:approvals — per tool
📊
Audit everything — Actor ID, role, tool, request payload, result, and decision are all stored
# Every tool checks this before running TOOL_SCOPES = { "deactivate_user": ["write:users"], "search_sops": ["read:sops"], "hybrid_query": ["read:hybrid"], }

Takeaways
What I'd tell you before starting
1
MCP is the standard. Learn it now — every major AI tool will speak it.
2
Never let AI run destructive tools unsupervised. Build the approval queue first.
3
One retrieval backend isn't enough. Combine vector, graph, and relational data.
4
Auth at the protocol layer, not the application layer. Scope every tool.
5
Docker Compose makes it ship-ready. Don't wait until the end to containerize.
